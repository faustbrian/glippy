# v0.5 Authoritative Testing Cleanup Receivers, 2026-08-21

## Decision

Recognize cleanup-managed returned resources registered through the exact
standard-library `testing.TB`, `*testing.B`, and `*testing.F` receiver
identities in addition to the existing `*testing.T` contract. Advance the
native effect schema and persistent-cache component to `native-effects-v12`.

## Evidence

The `go-libraries` corpus contains production test helpers that return a
cleanup-managed `*pgxpool.Pool` through `testing.TB`. Its benchmarks also
return cleanup-managed transports and PostgreSQL pools through `*testing.B`.
These are real duplicate-ownership false-positive boundaries for
`resource-not-closed`, not API-only speculation. `testing.TB` is also the
standard interface accepted by tests, benchmarks, and fuzz targets, while
`testing.B` and `testing.F` expose the same standard `Cleanup(func())`
lifetime contract.

## Observable Contract

The selected `Cleanup` method must belong to package `testing`, and its receiver
expression must have the exact unaliased type `*testing.T`, `testing.TB`,
`*testing.B`, or `*testing.F`. Interface dispatch through exact `testing.TB` is
accepted from its selected method identity. A named interface embedding
`testing.TB`, a user-defined `Cleanup(func())` interface, and every other
lookalike remain unmanaged.

All existing object-stability, callback, path, closure, delegation, package-
variant, no-return, and recursion boundaries remain unchanged. The extension
does not authorize arbitrary cleanup registries or infer that cleanup has
already executed in the caller.

## Behavioral Evidence

The focused regression initially left results returned through `testing.TB`,
`*testing.B`, and `*testing.F` unmanaged. The final analysis recognizes all
three while retaining diagnostics for a named `testing.TB` embedding and a
custom cleanup-only interface. Existing `*testing.T` and delegated-result
regressions remain unchanged.

`resource-not-closed` consumes the expanded fact to avoid assigning caller
ownership twice. `resource-used-after-close` continues tracking explicitly
closed cleanup-managed acquisitions because registration does not prove that
the callback has run.

## Cost And Adoption

Five complete one-iteration 100-function package-analysis samples using
`testing.TB` cleanup and exact delegation measured 104.69-116.38 ms,
10.85-11.45 MB, and 126,873-127,354 allocations on Go 1.26.7, Darwin arm64,
and an Apple M4 Max. This is directional rule evidence rather than a portable
release budget.

Non-mutating exact `resource-not-closed,resource-used-after-close` dogfood is
clean on Glippy and `go-libraries/pkg/prompts`. At external `go-libraries`
revision `3fe07983906f192a6cd983217a203d89696ffc28`, the real
`testing.TB` helper in `pkg/idempotency/postgres` and `*testing.B` helper in
`pkg/sequencer/postgres` produce no duplicate ownership finding. The
`pkg/queue/valkeystream` benchmark helper also remains unreported while its
separate fake-transport findings remain conservative. `pkg/http-client`
retains its established five findings. External bytes and pre-existing state
remain unchanged.

## Revisit Trigger

Admit another cleanup receiver only when authoritative lifetime semantics and a
real returned-resource pattern are both established. Do not infer cleanup
authority from method names or interface shape.
