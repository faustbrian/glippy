# v0.3 Semantic Correctness Pack, 2026-08-14

## Decision

The v0.3 semantic pack adds ten focused native rules:

- `ignored-append-result`
- `nil-map-write`
- `defer-before-error-check`
- `infinite-recursion`
- `ineffective-value-receiver-assignment`
- `impossible-interface-nil-comparison`
- `nan-comparison`
- `integer-division-before-conversion`
- `ineffective-url-query-mutation`
- `deferred-lock`

Two requested behaviors already have canonical rule identities and are not
duplicated:

| Requested behavior | Canonical Glippy rule | Tier | Preset |
| --- | --- | --- | --- |
| possible nil dereference | `nilness` | SSA | suspicious |
| `WaitGroup.Add` inside a launched goroutine | `waitgroup-misuse` | types | correctness |

Adding aliases for those behaviors would produce duplicate diagnostics when
their shared preset is enabled, split suppressions and baselines across two
IDs, and make `glippy explain` present two contracts for the same finding.

## Default policy

Rules with direct, constant behavior are in `correctness`. Rules that depend on
likely intent are in `suspicious`, including discarded append results,
value-receiver mutation, integer division before conversion, and cleanup
deferred before an acquisition error check.

The rules use the shared typed traversal and existing SSA engine. They do not
load a second package graph or build a second SSA program.

## Upstream and toolchain boundary

Current Staticcheck source was reviewed at
[`d69e7ee19e2d79b721aa696626cea310c807dd3e`](https://github.com/dominikh/go-tools/tree/d69e7ee19e2d79b721aa696626cea310c807dd3e).
The established defect classes map as follows:

| Glippy rule | Current upstream evidence | Glippy boundary |
| --- | --- | --- |
| `ignored-append-result` | Staticcheck SA4010 | Reports the valid explicit `_ = append(...)` form; a bare discarded append is already a type error |
| `nil-map-write` | Staticcheck SA5000 | Tracks definitely nil local maps through straight-line blocks and conservative if-branch joins |
| `defer-before-error-check` | Staticcheck SA5001 | Requires one acquisition tuple, the same resource and error objects, a deferred `Close`, and a later `err != nil` check without intervening reassignment |
| `infinite-recursion` | Staticcheck SA5007 | Reports only a body consisting of one direct self-call or return of a self-call |
| `ineffective-value-receiver-assignment` | Staticcheck SA4005 | Uses a conservative typed subset: direct fields, no method results, no promoted indirection, no later receiver observation, no closure capture, and no receiver address escape |
| `impossible-interface-nil-comparison` | Staticcheck SA4023 | Covers direct interface conversions of concrete values, including typed nil values; interface-valued operands and type parameters remain excluded |
| `nan-comparison` | Staticcheck SA4012 | Requires exact `math.NaN` object identity and equality or inequality comparison |
| `integer-division-before-conversion` | Related Staticcheck SA4025 | Glippy's suspicious rule covers nonconstant integer division converted afterward and excludes exact constant divisions |
| `ineffective-url-query-mutation` | Go `net/url.URL.Query` contract | Covers direct `Set`, `Add`, `Del`, `delete`, `clear`, and index assignment on the temporary map |
| `deferred-lock` | Related Staticcheck SA2003 | Requires exact `sync` `Lock` or `RLock` method identity; unlike SA2003, it diagnoses the deferred lock call without requiring a preceding immediate lock |

The Go compiler rejects some neighboring forms, such as a bare unused append
result, but accepts every admitted incorrect example. The supported default
`go vet` catalog does not provide these ten diagnostic identities. Glippy
therefore adds policy, suppression, baseline, deterministic reporting, and
source-range ownership without duplicating a compiler error.

## Precision and safety

All ten rules require types because object or method identity prevents reports
against shadowed built-ins, same-named user APIs, and unrelated receiver
methods. None offers a fix. The intended repair can require ownership or API
judgment, and successful parsing would not prove a semantic transformation
safe.

The correctness group contains only constant or directly ineffective behavior.
The suspicious group owns patterns where intent remains relevant:

- `_ = append(...)` can intentionally mutate an existing backing array;
- a copied receiver can be deliberately mutated and observed inside a method;
- integer truncation before conversion can be intentional; and
- some APIs return a usable resource together with a non-nil error.

The local nil-map analysis drops its definitely-nil fact when unmodeled control
flow assigns the map, a range clause can replace it, or its address escapes.
Those cases may produce false negatives, but they cannot turn uncertain state
into a correctness-level diagnostic.

Generated files and packages with type errors are excluded. All rules select at
Go 1.25 and Go 1.26 and do not select at Go 1.24. Suppressions remain exact by
rule ID; no alias is introduced for the two existing canonical behaviors.

## Behavioral evidence

The package fixtures establish:

- positive diagnostics for every rule;
- nearby valid non-diagnostics, including observed and returned value-receiver
  copies, exact constant division, conditional map initialization, typed nil
  interface conversion, resource reassignment, and `err == nil` branches;
- exact primary byte ranges and stable message keys;
- direct URL query mutation through methods, built-ins, and indexing;
- function and method recursion;
- generated-file exclusion, type-error exclusion, exact suppressions, and Go
  version selection; and
- absence of fixes for every diagnostic.

The one-iteration package benchmark on Go 1.26.6, Darwin arm64, and an Apple M4
Max measured `86,884,084 ns/op` for all ten rules together. It includes package
loading and is proportional admission evidence, not a stable latency budget.

A non-mutating dogfood run with only these ten rules enabled produced no
findings in the current Glippy working tree or in
`go-libraries/pkg/prompts` at
`95c9c5938607579e33e7723a57332ed8e5492fb0`. Both runs completed with module
lookup disabled during analysis after dependencies were prefetched into a
disposable cache. Neither repository was modified.

## Revisit trigger

Revisit the canonical identities only if either existing rule grows multiple
independently configurable diagnostic families that require distinct
suppressions, severities, or analysis costs. Revisit individual precision
boundaries when dogfood finds a false positive, a missed direct form becomes
common, or interprocedural SSA facts can materially improve signal without
raising the default analysis tier.
