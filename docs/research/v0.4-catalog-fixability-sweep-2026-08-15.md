# v0.4 Catalog Fixability Sweep, 2026-08-15

## Decision

The current catalog has 101 rules. Eighteen expose a named fix: three safe and
15 suggestion-only. No rule exposes an unsafe fix. The remaining 83 were
reviewed and intentionally retain no automatic transformation. This inventory
lists every current rule exactly once.

Fix count is not a quality target. A rule remains diagnostic-only when the
developer's intended correction is unknowable or when a credible repair owns
control flow, resource lifetime, synchronization, data shape, or public API
design beyond one local edit.

## Transaction Evidence

Fixes can declare exact required import bindings. The coordinator may add only
those bindings and may remove only an import made unused by accepted edits; it
does not run general import organization. Structured withheld-fix records
explain source-specific comment barriers. Package-aware fixing refreshes
remaining selections after each changed file, refuses generated targets before
any write, reparses and formats complete files, reruns typed analysis, and
reports conflicts or validation failures without silently choosing a winner.

The diverse-corpus rehearsal applied 82 fixes across fzf, Caddy, sqlc, and NATS
without a semantic or stale-edit failure. Eight additional NATS suggestions
were conservatively rejected by formatter comment-ownership validation and
left unchanged.
