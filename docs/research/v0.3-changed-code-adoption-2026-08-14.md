# v0.3 Changed-code Adoption, 2026-08-14

## Decision

Glippy supports `lint/check --new-from=<git-ref>` as a transient adoption
boundary, not as a weaker analysis mode. It resolves a deterministic merge
base, runs full-file and full-package analysis, and filters only the reporting
and fix-ownership surfaces afterward.

## Ownership model

- tracked modifications use the new-side zero-context Git diff ranges;
- modified renames compare both the old and current paths so unchanged lines
  retain identity;
- pure renames own no source lines;
- untracked files are wholly owned;
- deleted files have no current diagnostics;
- a diagnostic is new when its physical range intersects an owned line; and
- a fix is selectable only when every edit line and every final formatted
  source change is owned.

Tracked changed-line scopes are bound to the exact source digest observed
during resolution. Analysis or fix planning rejects a later source version
instead of applying stale line ownership. Untracked files remain wholly owned;
their ordinary diagnostic and fix identities still bind the exact analyzed
bytes.

Pre-existing diagnostics and formatting differences are counted separately in
schema-version-1 JSON. They do not affect the exit status and are not emitted
as actionable diagnostics. Package loading, suppressions, baselines, type
facts, CFG, and SSA still operate over complete source.

## Git boundary

The implementation invokes the local Git executable with cancellation,
optional locks disabled, and external diff, text conversion, and paging
disabled. It performs no fetch and therefore requires the selected base ref and
history to exist locally. Inherited `GIT_*` repository overrides and global or
system Git configuration are removed. The diff algorithm and attribute policy
are fixed, and every locally configured content-filter driver is overridden as
non-required with empty clean, smudge, and process commands before inspecting
the working tree. Multiple merge bases are sorted by full object ID and the
first is selected deterministically. Option-like and control-character base
values are rejected before execution.

## Revisit trigger

Revisit the merge-base policy if real criss-cross histories demonstrate that a
synthetic merge base materially improves precision. Revisit line ownership if
dogfood shows useful multi-line fixes rejected by the conservative complete
transformation check.
