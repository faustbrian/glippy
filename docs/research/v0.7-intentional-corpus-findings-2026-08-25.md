# v0.7 Intentional Corpus Findings, 2026-08-25

## Decision

Corpus adjudication distinguishes `intentional` diagnostics from
`false-positive` diagnostics. An intentional finding accurately matches the
documented rule contract, but the source deliberately accepts the reported
behavior. A false positive remains a diagnostic whose rule contract should not
match the source.

Intentional findings remain visible. Repositories that want them hidden must
use Glippy's ordinary narrow suppression contract. Glippy does not infer intent
from paths, comments, test files, fuzz targets, or repository identity.

## Containerd Evidence

At pinned containerd revision
`6c12665e1c31e7728d0e0eb1224288bd9153114b`,
`contrib/fuzz/archive_fuzz_test.go` creates an `archive/tar.Writer` over a local
`bytes.Buffer`, defers `Close`, and consumes `buf.Bytes()` before the deferred
close can write the footer. The close result is discarded. The fuzz target
deliberately accepts malformed archive material as input to the import target.

The diagnostic is therefore accurate and intentional. Suppressing all deferred
in-memory tar closes would be unsound: `archive/tar.Writer.Close` can still
report incomplete-entry state independently of underlying writer failures.
