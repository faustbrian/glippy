## Comparator Coverage

`go vet` completed without findings and does not report the three scanner
paths. Staticcheck reported 73 diagnostics: 52 API deprecations, five
simplifications, one ineffective assignment, one constant-declaration warning,
11 style diagnostics, and three unused helpers. Most are generated-code,
migration, style, or dead-code policy differences rather than missing default
Glippy correctness rules.

The `SA4006` finding in `internal/engine/clickhouse/convert.go` is a credible
general ineffective-assignment example. The converter computes a parameter
name and numeric fallback but never reads either value when constructing the
returned `ast.ParamRef`. Glippy's `overwritten-error` rule intentionally covers
only error-typed values, so this case joins the aggregate v0.6 missed-defect
queue for a separately admitted general rule rather than broadening the current
default rule without a precision contract.

## Decision

Retain all three recommended scanner diagnostics. sqlc requires no precision
correction from this run. Add general ineffective-assignment analysis to the
evidence queue using the independent sqlc and NATS occurrences; do not admit it
or enable it by default until its false-positive and cost boundaries are
proven.

The complete exact corpus must rerun at the latest Glippy revision before this
adjudication contributes to the v0.6 exit evidence.
