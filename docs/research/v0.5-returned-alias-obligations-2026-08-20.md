# v0.5 Returned-Alias Lifecycle Obligations, 2026-08-20

## Decision

Consume exact `returns-alias` project contracts in the shared lifecycle
obligation engine. When a contracted result is assigned directly back to the
same tracked transaction or closer whose argument it aliases, ownership has
returned to the caller and the preexisting obligation remains live.

This closes the remaining gap between the versioned contract schema and
built-in consumers. No contract field remains parsed, validated, cached, and
exposed without an admitted product behavior.

## Observable Contract

The analysis recognizes direct one-result assignments and tuple-result
assignments whose exact result and argument indexes match the configured
relationship. A guaranteed close or transaction-completion parameter effect
still discharges the obligation. A guaranteed transfer does not discharge it
when the same call is proven to return that object into the same tracked
variable.

An identical helper without a returned-alias contract retains the previous
conservative transfer boundary. Assigning the result to a different variable
does not create an alias group, and returned identity does not prove that a
resource remained open or closed while the helper executed.
When one multi-result call returns the same argument into both the tracked
object and another nonblank binding, the additional alias keeps the complete
assignment at the conservative transfer boundary.

Review hardening established two additional boundaries. A configured specific
terminal effect takes precedence when the same parameter also declares generic
ownership transfer, because configured effects are simultaneous guarantees.
When one assignment writes the tracked object more than once, only its final
left-to-right write can preserve the obligation; an earlier returned alias that
is overwritten is treated as a lost obligation.

Method-expression calls map their explicit receiver separately from configured
parameter indexes. Ordinary multi-RHS assignments match each source only to
its positional destination, while a single multi-result call retains its tuple
result mapping. These rules prevent both receiver-offset misses and unrelated
cross-product ownership transfers.

Lifecycle completion and binding state remain separate. A helper may complete
the original object even when a later duplicate target replaces the binding;
the obligation is discharged, but state-sensitive rules treat the replacement
binding as unknown. A final direct self-write does not replace the binding. A
contracted returned alias avoids replacement uncertainty, but only a separate
guaranteed close or completion effect establishes the resulting lifecycle
state.

## Behavioral Evidence

The focused lifecycle test configures an exact same-package transaction helper,
assigns its returned alias back to the tracked transaction, and requires the
existing `sql-transaction-not-completed` diagnostic at the original
acquisition. The initial run produced no diagnostic. Review regressions cover
tuple results, a later duplicate-target overwrite, combined completion and
transfer guarantees, method expressions, positional multi-assignment, and
assignment to another binding. A state-transition regression proves that a
later duplicate-target replacement is not treated as completed or closed. The
same fixture keeps an otherwise identical uncontracted helper non-reporting to
prove that ordinary return shape and naming do not imply the relationship. A
separate closer fixture exercises the shared resource consumer,
method-expression mapping, and combined close-transfer precedence.

The shared obligation implementation is used by resource and transaction
completion rules. State-transition consumers deliberately do not use returned
identity as evidence that open or closed state was preserved.

## Cost And Adoption

Five complete one-iteration package-analysis samples over 100 configured
transaction aliases on Go 1.26.6, Darwin arm64, and an Apple M4 Max measured a
91.73 ms median, 6,142,760 B/op, and 64,634 allocs/op. The observed timing
range was 89.47-195.80 ms; the cold first sample was the outlier. This is
directional regression evidence rather than a portable latency budget.

This batch advances the native effect schema and cache component from version
4 to version 5. Parameter summaries now distinguish terminal effects that may
occur from effects independently guaranteed on every returning path. The
distinction prevents a simultaneous close or transaction-completion guarantee
from being weakened by an alternative inferred transfer path, and the new
field participates in deterministic cache identity.

Non-mutating exact-rule dogfood completed without findings on Glippy and on
`go-libraries/pkg/prompts` at
`59252704b2bcbcfba4c390519ffb94c5870c01f8`. Both runs used one freshly built
working-tree binary with ordinary analysis network access disabled. The
prompts repository's pre-existing dirty state and `go.sum` digest
`5682cca758f3e1cc9931b18bccfe7111dc56825dc8e8a4549e4171a0ca46db4b`
remained unchanged.

## Revisit Trigger

Revisit the same-object boundary when real defects justify a bounded dynamic
alias model that can follow a returned value into a different local binding
without making joins, reassignment, escape, or state mutation speculative.
