# v0.5 Unconditional Result-State Facts, 2026-08-20

## Decision

Add a stable per-result nil-state summary to native effect facts and let
`writer-not-finalized` consume it only for an exact statically resolved return
call. This closes one bounded interprocedural error-flow gap without retaining
dependency syntax as lint input or treating possible success as proven success.

The native effect schema and cache component advance from version 7 to version
8. The digest includes each ordered stable function identity, result index, and
proven nil state.

## Observable Contract

A result state is recorded only for a nil-capable result when every explicit
normal return has the declared result arity, classifies the expression exactly,
and agrees on nil or non-nil. Built-in error results recognize exact nil,
`errors.New`, and `fmt.Errorf`. Other nil-capable results recognize exact nil,
address, function-literal, composite slice or map, `new`, and `make` forms.
Bare results, delegated or recursive returns, dynamic calls, typed nil errors,
unknown expressions, and conflicting states remain unknown.

Stable package-qualified function identities carry facts across independent
loads. When test or build variants expose the same identity, every variant must
publish the same result state; an absent or disagreeing state removes the fact.

`writer-not-finalized` accepts the fact only when the caller returns an exact
static call and the mapped callee result is the built-in `error` type. A single
error call maps result zero. A tuple delegation must have the same result arity
as the caller and maps the caller's sole built-in error index. Multiple error
results, dynamic calls, and unavailable facts remain conservative.

## Behavioral Evidence

The focused package regression initially produced zero diagnostics for four
missing finalizers followed by same-package or imported exact successful
helpers. It now reports the single-error and tuple forms in both source
boundaries. Nearby helpers returning a known failure, an unknown parameter, a
typed nil error, a recursive result, or a dynamically selected function remain
silent.

Unit evidence covers nil, non-nil, unknown, typed-nil, recursive, and
conflicting result summaries; stable identity across independent type loads;
package-variant intersection; deterministic digest ordering; content
sensitivity; and cancellation.

## Revisit Trigger

Revisit delegated result summarization only with a bounded fixed point that
detects recursion and preserves package-variant agreement. Revisit named bare
results only through path-sensitive result dataflow. Do not infer nil error
from assignability, typed nil values, dynamic dispatch, or a subset of normal
returns.
