# v0.8 Aggregate Budget Calibration, 2026-08-25

## Decision

The release campaign's stable aggregate process-tree peak-RSS ceiling for the
pinned typed workload is 3,221,225,472 bytes. The prior 2,147,483,648-byte
ceiling is rejected by native evidence on three supported runners. Exact
four-runner workflow `32814696805` proves the 3 GiB replacement on every
supported macOS and Linux architecture with Go 1.27.0.

The 2 GiB aggregate formatter peak-RSS ceiling and 250-millisecond editor
ceiling are unchanged. The 90-second formatter latency ceiling is rejected by
two native Darwin amd64 campaigns and is replaced by a stable 120-second
ceiling. The Go 1.26-era 105-second typed latency ceiling is rejected by two Go
1.27 Darwin amd64 campaigns and is replaced by a stable 240-second ceiling.
The same exact four-runner campaign proves both replacements and cross-runner
byte-for-byte archive reproducibility.

diagnostic-fingerprint, archive-execution, and resource gate. The dependent

workload-specific regression ceilings for the two immutable corpora, not
general latency or memory promises for arbitrary repositories.

## Diagnostic Boundary

Darwin arm64 normalized typed output changed from the historical fingerprint
`13f9c3dd006a105196c13f766a1c849a882754b3083979e9386c78cc2fdb53d2` to
`77f989f585934478c95acff13a0671521696ad036b9430f033968bcd203baba7`.
Workflow
[`32807509298`](https://github.com/faustbrian/glippy/actions/runs/32807509298)
retained the exact normalized output at Glippy revision `4a80b27`. Its SHA-256
is the replacement value above, and it contains 351 deterministic findings:

| Rule | Findings |
| --- | ---: |
| `discarded-error` | 343 |
| `resource-not-closed` | 5 |
| `unchecked-scanner-error` | 3 |

The counts match the previously accepted exact workload except for the former
single `nil-error-wrap` and `unchecked-writer-error` findings.

The workflow now provides an explicit diagnostic-comparison mode. Given a
historical Glippy revision, it runs the historical and current binaries on the
same immutable typed checkout and retains both complete normalized outputs plus
their exact unified diff.

Comparison run
[`32809489235`](https://github.com/faustbrian/glippy/actions/runs/32809489235)
used current revision `344dc3d32e4ff0e7a84213608464848cf8182a47`, historical
revision `835a2961d4e47c43e21c551ac56313a743f98667`, the same typed revision
`8a7cddfbb9088666eb981645285d7699e71dcb54`, and Go 1.26.5 on native Darwin
arm64. It reproduced the historical fingerprint and the candidate fingerprint
exactly. The retained 32-line unified diff has SHA-256
`6c265a40215564ee3296eff6a7ea6c48cbcdd6ef65634da472c56e77d479723d` and
contains only these removals:

- `nil-error-wrap` at `internal/cmd/parse.go:131`, where `err != nil` dominates
  the wrap and therefore contradicts an unconditional nil-result summary;
- `unchecked-writer-error` at `internal/codegen/golang/gen.go:252`, where the
  stable `bufio.Writer` terminates at a `bytes.Buffer` through an exact
  source-proven infallible `Write` result.

No other diagnostic identity, range, message, or ordering changed. The
candidate fingerprint is therefore accepted and now enforced by the ordinary
four-runner campaign.

The same campaign passed Linux amd64 and Linux arm64. Darwin arm64 stopped only
at the intentionally stale fingerprint. Darwin amd64 reached 90.950 seconds on
its first formatter sample, 0.950 seconds above the 90-second ceiling, after the
prior exact campaign recorded a 35.390-70.130-second range. That single marginal
observation initially left the ceiling unchanged for an exact rerun.

Exact rerun
[`32810535882`](https://github.com/faustbrian/glippy/actions/runs/32810535882)
at Glippy revision `aac0dd425092746c7c691be0eaafd937d5d979c2` then recorded
77.880 seconds for its first Darwin amd64 formatter sample and 99.660 seconds
for its second. The second independent breach disproves the 90-second ceiling
as a stable regression boundary. A 120-second provisional ceiling leaves 20.4%
headroom over the largest observation while remaining a bounded per-sample
maximum. Linux amd64, Linux arm64, and Darwin arm64 completed the same campaign;
Darwin amd64 stopped at the formatter ceiling, so cross-runner reproducibility
was correctly skipped. A complete Go 1.27 exact-candidate campaign remains
required before the replacement becomes stable release evidence.

## Go 1.27 Typed-Latency Calibration

Go 1.27 campaigns
[`32813174079`](https://github.com/faustbrian/glippy/actions/runs/32813174079)
and
[`32813770238`](https://github.com/faustbrian/glippy/actions/runs/32813770238)
independently rejected the retained 105-second Darwin amd64 typed ceiling. The
same immutable SQLC workload completed in 174.090 seconds and 105.910 seconds.
Both campaigns passed their five formatter samples on Darwin amd64 and all
resource gates on Linux amd64, Linux arm64, and Darwin arm64 before the typed
latency failure prevented archive reproduction.

The largest Go 1.27 observation is 97.9% above the Go 1.26.5 green campaign's
87.910-second Darwin amd64 result. A provisional 240-second ceiling leaves
65.910 seconds, or 37.9%, of headroom over the new maximum. This follows the
existing portable-calibration policy while retaining a bounded four-minute
cold-analysis limit. It is not a general typed-analysis promise and remains
unproven until a complete exact-candidate native campaign passes.

## Exit Requirement

Workflow `32814696805` satisfies the aggregate-budget exit requirement. The
120-second formatter, 240-second typed latency, and 3 GiB typed-memory ceilings
are stable release evidence for the pinned campaign. A final v0.9 candidate
must rerun the same workflow because later production changes invalidate exact-
revision evidence; recalibration requires new red and green native evidence.
