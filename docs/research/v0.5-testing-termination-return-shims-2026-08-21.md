# v0.5 Testing Termination Return Shims, 2026-08-21

## Decision

Do not report the zero-value declaration and return pair used solely to make a
value-returning function syntactically terminating after an exact
standard-library `testing` `FailNow`, `Fatal`, or `Fatalf` call.

## Evidence

The `go-libraries/pkg/http-client` corpus contains two generic channel helpers
whose timeout branch calls `t.Fatal`, declares `var zero Value`, and returns
that value. The `testing` call terminates the current goroutine, but removing
the final return makes the generic function fail Go's syntactic termination
check. A generic zero value also has no universal literal spelling, so the
uninitialized declaration is part of the conventional compiler-satisfying
shim rather than stale executable work.

The existing `unreachable-code` boundary already excluded a direct return or
built-in panic required after a proven no-return call. Reporting the preceding
zero-value declaration while accepting its immediately following return split
one compiler-required idiom into inconsistent results.

## Observable Contract

The exclusion applies only when all of these conditions hold:

- the containing function has at least one result;
- the immediately preceding expression statement resolves by `go/types` to
  package `testing` method `FailNow`, `Fatal`, or `Fatalf` and the shared
  no-return predicate proves that call terminal;
- the final two statements are one `var` declaration with no initializers and
  a return of every declared object exactly once with no other expression.

The declaration and return remain represented in source and receive no fix.

Empty or initialized declarations, extra work before the return, local no-return
helpers, user-defined methods with terminal-looking names, result-free
functions, missing type information, and malformed or ambiguous return shapes
remain diagnostics or fail closed. Direct `testing` skip calls retain their
separate intentional-disabled-test boundary.

## Behavioral Evidence

The focused regression initially reported the zero-value declaration after
exact `*testing.T`, `testing.TB`, `*testing.B`, and `*testing.F` termination
calls. The final result suppresses those four shims while retaining findings
for a package-local no-return helper, an initialized declaration, work retained
before a return, a result-free function, a custom `Fatal` lookalike, and work
after what would otherwise be a valid shim. The earlier branch, label, return,
panic, skip, and suggestion-fix regression remains unchanged.

## Cost And Adoption

Five complete one-iteration `unreachable-code` package-load samples measured
113.95-203.13 ms, 5.73-6.41 MB, and 48,387-48,845 allocations on Go 1.26.7,
Darwin arm64, and an Apple M4 Max. This is directional per-rule evidence rather
than a portable release budget.

Non-mutating exact-rule dogfood is clean on Glippy and
`go-libraries/pkg/prompts`. At external `go-libraries` revision
`8409c3d568cc0b921aa271f6dc0cc6dcfcc40625`, both generic `*testing.T` helpers
in `pkg/http-client` are clean. External bytes and pre-existing state remain
unchanged.

## Revisit Trigger

Admit another multi-statement syntactic shim only from a repeated real pattern
whose complete statement sequence can be proven side-effect-free and required
for Go termination or typing. Do not suppress arbitrary unreachable setup
merely because a later statement returns.
