# v0.6 `nil-context` Optional-Helper Precision, 2026-08-24

## Evidence

Pinned corpus run `32698988231` at exact Glippy revision `7840a0c` produced
two recommended `nil-context` findings in Grafana revision
`45a80328c0dd976720af0366efcad0787762b142`:

- `6ce550219f31792a7c835d3104663d7c94ec36e1be69f06b4779575dcb11279e`
  for the transaction `Commit` path; and
- `37e5517cd0313788e93c52512a33c544069cf932d6f6c2e0cab4f682c79eb76e`
  for the transaction `Rollback` path.

Both calls deliberately pass nil to the private `otelTx.startSpan` helper.
That helper names the parameter `optionalCtx`, tests it for nil before every
context operation, and permits nil to select an unlinked transaction span.
The calls also carry the repository's existing Staticcheck suppression. The
first divergence is Glippy's prior name-and-type-only inference: it treated
every direct nil passed to an exact `context.Context` parameter as defective
without inspecting an available private callee body.

## Decision

Do not report a direct nil argument when all of the following are proven:

1. static dispatch resolves the call to an unexported function or method in the
   current package;
2. the exact declaration body is available;
3. evaluating the selected parameter as nil reaches an explicit comparison
   against the predeclared nil identifier;
4. a `ctx != nil` guard has no `else`, or a `ctx == nil` guard contains only an
   immediate return;
5. every other reachable use on that nil path is a direct return of the
   parameter; and
6. the nil path does not contain branch or label control flow.

Exported callees, dependency calls, interface dispatch, method expressions,
variadic context elements, unavailable declarations, indirect parameter uses,
assignments, and unproven control flow retain the diagnostic. This is a bounded
source proof, not a function-name, parameter-name, path, repository, comment,
or foreign-suppression exception.

## Behavioral Evidence

The focused regression initially reported three diagnostics instead of the two
expected before the production change. The completed fixture uses a private
method with two guarded context operations and a direct return, matching the
Grafana shape. It also proves that an exact early-return nil guard is accepted,
while an exported nil-tolerant helper, private helpers that panic directly or
through another function, and an unguarded private helper still report.
Interface dispatch, method values, method expressions, and dependency calls
also retain diagnostics. Existing variadic and ordinary context-position
coverage remains green.

The complete exact corpus must rerun at the resulting pushed revision before
this correction contributes to the v0.6 exit evidence.
