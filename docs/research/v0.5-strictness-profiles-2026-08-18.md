# v0.5 Curated Strictness Profiles, 2026-08-18

## Decision

The v0.5 policy milestone is complete for four curated profiles over Glippy's
existing groups and exact rule policy:

- `default` selects correctness;
- `recommended` adds 19 reviewed low-noise suspicious rules;
- `strict` selects correctness, suspicious, performance, complexity, and style;
  and
- `pedantic` adds the complete pedantic group.

Restriction rules remain exact-ID-only, and migration remains unavailable
without an explicit target. Selecting a profile is mutually exclusive with the
singular and plural preset fields.

## Resolution And Identity

Profile rules remain separate from user-authored `lint.rules`. The effective
order is profile composition, exact rules, ordered path overrides, exact CLI
filters, ordered lint levels, and warning escalation. The same resolution path
is used by syntax, types, CFG, SSA, CLI, combined check, and LSP analysis.

Configuration identity records the profile name, normalized groups, and the
resolved exact profile policy. An exact override therefore remains
distinguishable from profile enablement, while a future profile catalog change
invalidates persistent and workspace analysis results.

## User Surface

Omitting all profile and preset fields selects `default`. `glippy init` writes
that identity, while `glippy init --profile=<name>` accepts all four profiles
and rejects unknown values before creating a file. Bash, Zsh, and Fish
completion expose the same values.

`glippy config show` reports the selected profile and attributes enabled rules
to that profile, an exact override, or the last matching path override. Custom
preset composition reports `profile: none`.

## Behavioral Evidence

The red tests failed because the configuration type, decoder, initialization
flag, profile provenance, and lint selection did not exist. The green tests
exercise:

- implicit and explicit profile decoding and exact composition;
- unknown and ambiguous profile rejection;
- profile and resolved-policy cache identity;
- profile preservation through path policy;
- initialization selection and pre-write rejection;
- catalog-valid resolution for every profile;
- rule-level `config show` provenance;
- recommended-profile lint findings plus exact and path-scoped disabling; and
- deterministic Bash, Zsh, and Fish completion.

Fresh final-tree verification passed the complete test suite, affected-package
race suite, `go vet`, module tidy-diff check, generated rule documentation,
Glippy formatter check, candidate build, and candidate self-check. All Go work
used task-owned disposable build caches, which were removed after each bounded
run.
