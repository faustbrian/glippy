# v0.7 Testing-Failure Wrapper Provenance, 2026-08-25

## Decision

Propagate a distinct testing-failure provenance fact through exact
selected-module no-return wrappers. `unreachable-code` may accept one final
bare return shim after such a call, matching its existing direct
`testing.FailNow`, `Fatal`, and `Fatalf` behavior. The ordinary no-return fact
remains separate because panic, process exit, testing skip, and mixed terminal
behavior do not prove a testing-failure compatibility shim.

## Corpus Evidence And First Divergence

Pinned Kubernetes corpus revision
`e81f39c0e03ce8ed8e2660c9147b391edd9e262b` produced 17 default
`unreachable-code` false positives, repeated in recommended. Each was a final
return immediately after a source-proven no-return test-failure wrapper. The
same corpus retained 17 actionable findings where cleanup or post-mortem work
followed a no-return call.

The first divergence was not no-return discovery: the wrapper already made the
following return unreachable. The control-flow context preserved testing-skip
provenance across wrappers but exposed testing-failure identity only for direct
standard-library calls, so the return-shim policy could not distinguish a
testing-failure wrapper from an arbitrary no-return helper.

## Precision Contract

A selected-module function has testing-failure provenance only when it is
proven no-return and every live terminal CFG block ends in a statically resolved
call with the same provenance. The authoritative roots are receiver methods
`FailNow`, `Fatal`, and `Fatalf` from package `testing`. Acyclic wrapper chains
are bounded by the shared no-return recursion limit; recursive wrapper cycles
remain unclassified.

Package variants must all agree before the stable function identity is
exported. A mixed testing-failure and panic wrapper, a testing skip, process
exit, dynamic call, unresolved callee, returning path, or name-only lookalike
does not qualify. The rule suppresses only a sole final bare return; retained
work and value-return compatibility shims keep their existing contracts.

## Cache And Interaction Boundary

The native effect schema and persistent-cache component advance from version
14 to version 15. The digest includes canonically ordered testing-failure
identities, so changing wrapper provenance or package-variant agreement
invalidates affected native results. Testing-failure and testing-skip facts
remain distinct: skips continue to suppress an intentionally disabled test
body, while failures authorize only the narrow return shim.

## Behavioral Evidence

The imported-wrapper regression initially reported four returns. The final
contract suppresses direct and transitively wrapped testing failures while
retaining diagnostics after mixed failure/panic and panic-only wrappers. Unit
fixtures cover cross-load stable identity, cloning, package-variant
intersection, authoritative method identity, name-only lookalikes, and effect
digest sensitivity.

The complete pinned corpus must rerun during v0.8 before the 17 historical
fingerprints are considered removed at exact revision. No external repository
is modified by this local regression evidence.

## Revisit Triggers

Broaden value-return shims through wrapper facts only if real corpus examples
justify a source-safe zero-value contract. Do not infer testing failure from
function names, testing-like receiver types, comments, or a single terminal
path. Keep actionable work after a terminal failure visible.
