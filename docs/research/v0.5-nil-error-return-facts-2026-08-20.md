# v0.5 Nil-Error Return Facts, 2026-08-20

## Decision

Allow `nil-error-wrap` to consume the existing versioned nil/error return-state
facts for selected local helpers. The rule still reports only an exact built-in
`error` operand proven nil at one exact `fmt.Errorf` `%w` call.

This adds no inference source. It makes already computed cross-package facts
observable to the error-wrapping consumer and declares that requirement in the
rule metadata and cache selection.

## Observable Contract

The error must be a direct extraction from one statically resolved tuple call.
Another extracted result must be proven nil or non-nil by an exact comparison
edge that dominates the formatting call. The observed state proves the error
nil only when it contradicts the helper summary for every non-nil-error return:

- if every non-nil error returns a nil sibling, a non-nil sibling proves the
  error nil;
- if every non-nil error returns a non-nil sibling, a nil sibling proves the
  error nil.

Dynamic calls, phis, delegated results, conflicting return summaries,
unavailable dependency facts, typed nil errors, and sibling states without
exact edge dominance remain unknown. The existing literal, zero-value, and
direct error-comparison proofs retain their behavior.

## Behavioral Evidence

The focused cross-package regression initially produced no diagnostics. It now
reports the `%w` operand reached through a non-nil sibling when every non-nil
error returns nil, and the operand reached through a nil sibling under the
opposite exact relationship. Helpers whose non-nil-error results match the
observed sibling or conflict across returns remain silent.

The fixture imports the helper as dependency source but retains only the root
source as a diagnostic target, exercising the production effect-loading and
source-ownership boundaries.

## Cost And Adoption

Five complete 100-function package-analysis samples on Go 1.26.6, Darwin
arm64, and an Apple M4 Max measured:

| Sample | Time | Bytes | Allocations |
| ---: | ---: | ---: | ---: |
| 1 | 64.95 ms | 5,452,244 | 56,981 |
| 2 | 65.94 ms | 5,451,276 | 56,976 |
| 3 | 65.02 ms | 5,452,933 | 56,987 |
| 4 | 65.05 ms | 5,449,380 | 56,976 |
| 5 | 65.34 ms | 5,449,386 | 56,972 |

Exact-rule runs produced no findings on Glippy,
`go-libraries/pkg/prompts`, or `go-libraries/pkg/http-client`. The external
repositories retained their pre-existing bytes and status.

## Revisit Trigger

Revisit standard-library return relationships only through a reviewed exact
symbol table or another versioned fact source. Revisit phis and delegated
results only when their identity and dominance can be proven without widening
the rule from definite to possible nil wrapping.
