The actionable response-body findings are in
`pkg/services/rendering/http_mode.go`, two Azure Monitor implementation files,
and `scripts/build/release_publisher/publisher.go`. Each successful HTTP path
can return without closing or transferring the response body.

All 15 rows findings follow direct `database/sql.Rows.Next` loops that can
normally return accumulated or partial results without checking the matching
`Rows.Err`. They span the legacy collection, dashboard and IAM stores, resource
permissions, authorization stores, and unified-search document builder. The
scanner finding in `pkg/setting/setting_test.go` has the same terminal-error
loss for `bufio.Scanner`.

The nine nilness findings identify seven tautological or impossible nil checks
and two source locations that dereference a value proved nil. The three
`nil-error-wrap` findings wrap errors proved nil on their paths, and the
identical branch in the access-control resource-permission test duplicates the
preceding branch body. These are actionable under the existing rule contracts.

`pkg/util/xorm/xorm.go` calls `rand.Int64N` from a file whose source version is
Go 1.21 even though that API requires Go 1.22. Go vet reports the same source-
version incompatibility.

The eight non-actionable findings are:

- two `nil-context` calls in `pkg/storage/unified/sql/db/otel/otel.go` pass nil
  to an unexported helper whose body explicitly treats the parameter as
  optional before using it. The general private-helper precision correction is
  already implemented; no Grafana exception is required;
- four final returns in `pkg/storage/unified/sql/db/mocks/util.go` and one in
  `pkg/tsdb/azuremonitor/metrics/url-builder_test.go` follow `testing.Fatal` or
  `Fatalf`. They are intentional compile-time return shims after a proven test
  terminator. The narrowed no-return branch-shim correction is already
  implemented; and
- `pkg/services/apiserver/builder/helper.go` flushes a CSV writer inside a
  literal `if false` audit block. The block cannot execute. The shared CFG does
  not fold typed boolean constants, so Glippy now excludes CSV, rows, and
  scanner lifecycle candidates nested in constant-dead `if`, `else`, and
  classic `for` branches while retaining runtime-conditional findings.

The run analyzed 4,691 owned files across 1,393 packages and loaded 5,385
files. Reported phase durations were 1,304.8 seconds for default, 637.4 seconds
for recommended, 818.0 seconds for strict, and 978.5 seconds for pedantic.
Cumulative allocations ranged from 28.94 GiB to 32.54 GiB; they are not peak-
resident-memory measurements and do not establish a release budget. No profile
crashed, emitted invalid machine output, or ended incomplete.

## Comparator Coverage

Go vet reports only the same `rand.Int64N` source-version incompatibility.

Staticcheck reports 1,377 `SA1019` migration findings, 46 unused-code findings,
and broader style and simplification policy that does not belong in Glippy's
default correctness profile. Its two `SA1012` findings are the intentional
nil-context helper calls above. Of its three `SA4006` findings, two deliberately
retain a traced context for the used span or future traced work and carry
explicit suppressions. The third computes `colName` in
`pkg/util/xorm/session_find.go` but never reads it and is added to the general
ineffective-assignment queue.

Staticcheck also reports two `SA1024` findings where
`pkg/util/xorm/dialect_postgres.go` uses `strings.TrimRight` with SQL type
suffixes. `TrimRight` interprets those strings as cutsets rather than exact
suffixes and can remove valid trailing characters after `HasSuffix` succeeds.
This is a separate standard-library-misuse candidate in the missed-defect
queue. Its `SA4004` finding is a deliberate first-row query loop that breaks
after the first scan and does not establish a defect or default-rule candidate.

## Decision

Retain all 34 actionable diagnostics under their current rule contracts. The
three general precision corrections remove all eight intentional or unreachable
findings without a Grafana-specific suppression. Add ineffective assignment and
exact-suffix trimming to the evidence-backed rule queue.

The complete exact corpus must rerun at the latest Glippy revision before this
adjudication contributes to the v0.6 exit evidence.
