# v0.5 Direct Receiver Effect Consumption, 2026-08-20

## Decision

Consume the existing conservative receiver terminal-effect summary at direct
generic resource lifecycle call sites. A statically resolved method whose
summary guarantees close discharges the caller's `resource-not-closed`
obligation and establishes closed state for `resource-used-after-close`.

This does not add a new inference source or broaden source selection. It makes
the already versioned receiver fact observable outside cleanup-managed result
callbacks.

## Observable Contract

Direct method calls and method expressions use the exact `go/types` receiver
object. A method-expression receiver is not also processed as an ordinary
parameter. The call is terminal only when the receiver summary guarantees
close on every normally returning path.

Conditional or asynchronous closure, dynamic or interface dispatch, promoted
methods on an outer receiver, aliases, receiver reassignment, address escape,
unresolved recursion, conflicting package variants, and missing summaries do
not discharge an obligation or establish closed state. Existing explicit
`Close` calls and parameter close effects retain their behavior.

## Behavioral Evidence

The focused `resource-not-closed` regression initially reported direct
`Shutdown` and method-expression `Shutdown` calls whose receiver implementation
unconditionally called `Close`. It retained the conditional, dynamic, and
promoted-receiver findings after the implementation.

The focused `resource-used-after-close` regression initially reported no
diagnostics after those same guaranteed receiver calls. It now reports both
subsequent reads and relates each operation to its unique terminal call, while
a conditional receiver summary remains unknown.

## Cost And Adoption

Five complete one-iteration 100-function benchmark samples on Go 1.26.6,
Darwin arm64, and an Apple M4 Max measured:

- `resource-not-closed`: 59.57-85.96 ms, approximately 2.11 MB, and
  17,029-17,033 allocations per operation;
- `resource-used-after-close`: 26.24-40.54 ms, approximately 5.39 MB, and
  63,084-63,086 allocations per operation.

Against `go-libraries/pkg/http-client` at
`0e0240b1fdcefaa73619b8d0a5d0dfc778d9e2f0`, the exact
`resource-not-closed` run decreased from 12 findings to 10. The removed
findings are the two circuit breakers that call the separately versioned local
module's proven `Breaker.Shutdown` receiver directly. The ten retained findings
remain outside this proof. The external repository bytes were not modified.

## Revisit Trigger

Revisit promoted receivers only if object identity across embedding can be
proved without attributing an inner method's effect to the outer resource.
Revisit dynamic dispatch only with exact bounded implementation-set evidence.
