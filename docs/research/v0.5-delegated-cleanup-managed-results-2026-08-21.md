# v0.5 Delegated Cleanup-Managed Results, 2026-08-21

## Decision

Allow source-derived cleanup-managed result facts to cross exact static
single-result and same-arity tuple delegation through the bounded
selected-package fact traversal. Advance the native effect schema and
persistent-cache component to `native-effects-v11`.

## Observable Contract

Every explicit return must delegate the exact result to a statically resolved
callee result that is already proven cleanup-managed. A separately returned
single-result call maps to result zero. A sole multi-value call must have the
same result count as the wrapper. In both forms, the caller and callee result
types must be exactly identical.

Same-layer definitions resolve lazily through at most 4,096 active definitions.
Imported selected-package calls consume only stable facts completed by an
earlier dependency layer and intersected across package variants. Recursive
cycles, dynamic calls, conversions, mismatched result counts or types,
unavailable facts, mixed managed and unmanaged returns, and functions or
deferred calls proven not to return remain unmanaged.

`resource-not-closed` consumes the delegated fact and does not assign the
caller a duplicate ownership obligation. `resource-used-after-close` continues
to track the acquired value because test cleanup does not prove that the value
is already closed during the caller.

## Behavioral Evidence

The focused same-package regression initially reported both a two-hop delegated
single result and a delegated tuple result. Recursive, dynamic, and mixed
wrappers also reported and remain conservative. The focused analysis matrix
additionally retains no facts for mutual recursion, conversions, always-
panicking defers, and unreachable returns.

The imported selected-module regression initially reported delegated single
and tuple results while retaining direct cleanup-managed behavior. Both
delegated findings are removed after stable dependency-layer facts propagate.
A delegated cleanup-managed acquisition that is directly closed and then read
still produces the established `resource-used-after-close` diagnostic.

## Cost And Adoption

Five complete one-iteration 100-function package-analysis samples on Go 1.26.7,
Darwin arm64, and an Apple M4 Max measured:

| Sample | Time | Bytes | Allocations |
| ---: | ---: | ---: | ---: |
| 1 | 105.29 ms | 11,368,920 | 117,245 |
| 2 | 101.55 ms | 10,789,720 | 116,796 |
| 3 | 102.93 ms | 10,787,592 | 116,792 |
| 4 | 101.82 ms | 10,777,888 | 116,776 |
| 5 | 99.06 ms | 10,774,432 | 116,768 |

Non-mutating exact `resource-not-closed,resource-used-after-close` dogfood is
clean on Glippy and `go-libraries/pkg/prompts`. At external revision
`3fe07983906f192a6cd983217a203d89696ffc28`,
`go-libraries/pkg/http-client` reports five `resource-not-closed` findings
under the established conservative ownership boundary and has no
`resource-used-after-close` finding. The external repository revision and
pre-existing dirty state remained unchanged.

## Revisit Trigger

Extend beyond exact return delegation only when a repeated ownership pattern
has source-proven identity and lifetime semantics. Revisit recursive summaries
only if a monotone fixed point can establish a fact without accepting a cycle
as evidence for itself.
