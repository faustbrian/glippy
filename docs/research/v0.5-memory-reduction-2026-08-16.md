# v0.5 Typed-Analysis Memory Reduction, 2026-08-16

## Decision

The first v0.5 scale gate is complete on the recorded reference workload.
Fact-bearing adapted analyzers retain exact dependency bytes, digests, package
ASTs, type information, and imported facts without also retaining formatter
token, trivia, comment, directive, and reconstruction indexes for every
dependency file.

The change reduces the worst observed optimized sample from the exact
7,369,064,448-byte baseline to 3,463,626,752 bytes, a 53.00% reduction. All
four optimized samples remain below the 3,684,532,224-byte half-baseline gate
and produce byte-identical diagnostics.

## Workload

- Host: Apple M4 Max, Darwin arm64, 128 GiB RAM.
- Toolchain: Go 1.26.5.
- Corpus: `github.com/sqlc-dev/sqlc` at
  `8a7cddfbb9088666eb981645285d7699e71dcb54`.
- Policy: default `correctness` plus `-Wsuspicious`.
- Command: `glippy lint -Wsuspicious ./...`.
- Build and module caches: task-owned; network module lookup disabled.
- Findings: 2,839 text-output lines with raw SHA-256
  `ba9cb250ae5a5a3776c43582c8589670f85acd5a9f74bfc9e68e329090237737`
  and checkout-normalized SHA-256
  `030f4474aec74877307118376e77e8ad7254a46c32777242fd11e3223c7282d0`.

The earlier suspicious-only configuration was not the release workload. It
used about 1.3 GiB because it did not select the default correctness rules.
Adding correctness selected `printf-arguments`, whose imported wrapper facts
requested dependency syntax and exposed the retention problem.

## Root Cause

`go/packages` correctly loaded dependency syntax and type information for the
fact graph. Glippy's parser callback additionally constructed the complete
lossless formatter source model for every dependency file and retained both
representations for the full run.

The exact-workload heap profile immediately after package loading retained
4,425.15 MiB. Its largest live owners were:

| Owner | Retained heap |
| --- | ---: |
| source reconstruction pieces | 1,104.72 MiB |
| source token scanning | 755.01 MiB |
| type-and-value recording | 521.56 MiB |
| source trivia | 465.40 MiB |
| Go parser operands | 245.01 MiB |
| cloned source bytes | 191.95 MiB |

The first divergence was therefore dependency source fidelity, not Go 1.26.6,
CPU parallelism, the garbage-collector limit, CFG, SSA, or rule diagnostics.

## Implementation Boundary

The package parser now reserves and retains one exact immutable byte version
while parsing. After root ownership is known:

- reporter-visible root files receive the complete lossless source model;
- fact-only dependency files retain bytes, digest, metadata, physical ranges,
  package AST, and type information but omit formatter-only indexes; and
- native rules that explicitly declare dependency syntax continue receiving
  fully indexed dependency source.

Compact dependency source is analyzable but cannot satisfy `CanFormat`.
Dependency diagnostics and fixes remain non-targets, imported facts retain the
same type identities, and cache keys retain the same exact source digests.

## Durable Gate

`benchmarks/peak-rss.sh` now measures the actual correctness-plus-suspicious
typed workload with `lint -Wsuspicious`. It accepts a pinned typed corpus,
revision, RSS and elapsed budgets, and an optional expected diagnostic digest.
Before hashing, the gate replaces the selected typed root with
`<TYPED_ROOT>` so the fingerprint is independent of checkout location.
The reference gate is:

```sh
GLIPPY_PEAK_RSS_RUNS=3 \
GLIPPY_PEAK_RSS_TYPED_ROOT=/path/to/sqlc \
GLIPPY_PEAK_RSS_TYPED_REVISION=8a7cddfbb9088666eb981645285d7699e71dcb54 \
GLIPPY_PEAK_RSS_TYPED_BUDGET_BYTES=3684532224 \
GLIPPY_PEAK_RSS_TYPED_BUDGET_SECONDS=40 \
GLIPPY_PEAK_RSS_TYPED_OUTPUT_SHA256=030f4474aec74877307118376e77e8ad7254a46c32777242fd11e3223c7282d0 \
./benchmarks/peak-rss.sh
```

The corpus remains external and must be acquired at the pinned revision; it is
not copied into this repository.

## Remaining Scale Work

This closes the explicit 50% v0.5 RSS gate. It does not yet provide persistent
incremental LSP analysis, memory-aware worker scheduling, package-wave release
of type graphs, lazy SSA, or portable release budgets. Those remain later v0.5
tracks rather than conditions hidden inside this result.
