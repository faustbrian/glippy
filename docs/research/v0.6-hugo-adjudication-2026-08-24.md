# v0.6 Hugo Adjudication, 2026-08-24

## Evidence

Pinned corpus run `32698988231` used Glippy revision
`7840a0c03cf0d58ca0994ebd52e8d5b934ceeabf` and Hugo revision
`76a5e1880ab46688155b02e99bab9be2a6134492`. All four profiles completed:

| Profile | Findings |
| --- | ---: |
| default | 3 |
| recommended | 8 |

Manual review classifies five recommended findings as actionable and all three
default findings as intentional no-return control-flow shims.

The actionable findings are:

- `markup/asciidocext/internal/converter.go` checks the already cleared
  `html.Parse` error after a callback traversal that cannot assign that error;
  the condition is impossible and may be stale intended error propagation;
- `modules/client.go` can return either no rewrite or partial rewritten module
  content after a terminal scanner failure;
- `modules/collect.go` can retain partial vendored-module state and return nil
  after a terminal scanner failure;
- `resources/images/image.go` checks whether `NewWepCodec` returned nil even
  though the pinned constructor unconditionally returns a non-nil codec and a
  nil error; and
- `tpl/internal/go_templates/texttemplate/exec_test.go` overwrites the parse
  error before observing it, allowing a parser regression to be hidden behind
  execution behavior.

The three `unreachable-code` findings are final unlabeled `break` statements
after direct calls to `(*state).errorf`. The pinned helper always panics, and
the same branch shape is retained in Go's `text/template` implementation. The
breaks preserve the intended switch exit if that helper's terminal contract is
ever changed; they are not actionable dead work. Glippy now accepts only a
final unlabeled `break` or `continue` immediately after a direct proven
no-return helper call. Labeled branches, compound terminal flow, retained work,
and separate reachable breaks remain diagnostics, and accepted break shims do
not make their owner appear reachable.

The run analyzed 889 owned files across 384 packages and 1,032 loaded files.
Artifact timings were 1,130.5 seconds for the cold default run, 68.0 seconds
for recommended, 90.7 seconds for strict, and 107.4 seconds for pedantic.
Reported cumulative allocations ranged from 5.48 GiB to 6.08 GiB; they are not
peak-resident-memory measurements and do not establish a release budget. No
profile crashed, emitted invalid machine output, or ended incomplete.

## Comparator Coverage

`go vet` completed without findings. Staticcheck reported five uses of Hugo's
own deprecated compatibility fields and one `SA4006` ineffective assignment in
`hugolib/integrationtest_builder.go`. The compatibility-field uses are
intentional migration debt. The `end` variable is incremented while preparing
missing-file debug context but is never consumed, so the assignment is
actionable and provides a third independent corpus example for the queued
general ineffective-assignment rule.

## Decision

Retain all five nilness, scanner, and overwritten-error diagnostics. Suppress
only the three direct proven-no-return loop-control shims through the narrowed
`unreachable-code` contract. Hugo requires no other precision correction from
this run.

The complete exact corpus must rerun at the latest Glippy revision before this
adjudication contributes to the v0.6 exit evidence.
