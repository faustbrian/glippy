# v0.4 Fix-Owned Import Insertion Evidence, 2026-08-15

## Decision

Glippy fixes may declare exact required import path and local-name bindings.
The single-file coordinator, rather than the formatter or individual rule,
owns insertion, collision detection, fix-caused removal, and machine
provenance. This extends ADR 0018 without introducing general import
organization.

The first consumer is the suggestion-only `unsafe-host-port` repair. The
upstream analyzer can diagnose a `fmt.Sprintf` declaration in one file because
another file passes the value to `net.Dial`; its replacement uses
`net.JoinHostPort` in the diagnosed file. That file may not already import
`net`, so expression edits alone cannot pass typed validation.

## Observable Contract

- Native and adapted fixes carry canonically ordered exact path/name
  requirements.
- Analyzer mappings and native findings reject invalid, duplicate, or
  incompatible requirements.
- Analyzer and native cache schema version 3 persists and revalidates the
  requirements.
- Accepted fixes requiring incompatible bindings are all rejected rather than
  selecting a winner.
- An existing exact binding is reused. A conflicting path, name, package
  declaration, or newly introduced locally resolved selector rejects the fix.
- One safely represented grouped declaration may receive appended
  specifications without changing existing comments or groups. Otherwise the
  coordinator adds independent declarations.
- Imports required by accepted fixes cannot be removed as newly unused.
- Additions and fix-caused removals are sorted and reported separately as
  `add` and `remove` import changes.
- Parsing, canonical formatting, fresh analysis, source-version validation,
  atomic replacement, and second-run idempotency remain unchanged.

## Red-Green Evidence

The initial coordinator regression replaced `0` with `net.IPv4len` and
declared the exact `net` binding. Before implementation, coordination applied
the expression edit but returned no import change and produced source with an
undefined `net` identifier.

The package-level CLI regression declares an address with `fmt.Sprintf` in
`address.go` and passes it to `net.Dial` from `dial.go`. Before the analyzer
mapping declared its requirement, the suggestion was rejected during typed
validation because the diagnosed file had no `net` binding. The completed
transaction:

1. replaces `fmt.Sprintf` with `net.JoinHostPort` in `address.go`;
2. adds `net` to `address.go`;
3. removes the now-unused `fmt` import from `address.go`;
4. leaves `dial.go` byte-identical;
5. reports one applied named fix plus ordered import additions and removals;
6. completes fresh package analysis; and
7. produces no diagnostic, fix, import change, or source change on a second
   invocation.

Focused coordinator fixtures also cover an existing exact import, an aliased
requirement, comments and blank groups, incompatible accepted fixes, an
existing inexact binding, a target-local collision, an unrelated same-name
local, retention required by another accepted fix, deterministic multiple
additions, and rollback after final validation.

## Deliberate Boundaries

Glippy does not infer imports from replacement text, discover package names,
sort or merge declarations, choose a competing alias, rewrite blank or dot
imports, or repair unrelated unused imports. Newly introduced local selector
collisions are detected conservatively by resolving the edited syntax and
comparing it with the original source. Revisit that boundary only if dogfood
shows useful fixes withheld by a repeated non-conflicting form.
