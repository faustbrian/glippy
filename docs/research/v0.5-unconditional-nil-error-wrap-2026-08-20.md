# v0.5 Unconditional Nil-Error Wrapping, 2026-08-20

## Decision

Allow `nil-error-wrap` to consume version-8 unconditional result-state facts
for exact static calls. A direct helper result or tuple extraction proven nil
on every explicit normal return now exposes the malformed non-nil error created
by `fmt.Errorf` with `%w`.

## Observable Contract

The wrapped operand must have the exact built-in `error` type and map directly
to an SSA call or an extraction from one SSA call. The call must have an exact
static callee, and the mapped result must have a stable nil fact. Local
variables preserve the same direct SSA value; phis and other forwarding do not.

Dynamic calls, recursive or delegated helper returns, typed nil errors,
unknown or conflicting return expressions, multiple package variants that do
not agree, and unavailable dependency facts remain conservative. A named
result is ineligible when its address is taken or a function literal captures
it because deferred or asynchronous execution can replace the explicit return
value.

## Behavioral Evidence

The first focused package regression produced no diagnostics for four exact
same-package or imported direct and tuple results. The initial consumer reported
all four but dogfood then found three false positives in Glippy's analyzer
adapter. Those helpers explicitly returned nil before deferred panic recovery
could overwrite the named error result.

A focused fact regression reproduced the safety defect for deferred capture and
address escape. The final inference rejects both while retaining a harmless
unrelated defer. The package fixture reports the four proven nil results and
stays silent for known failures, unknown parameters, dynamic calls, recursive
results, typed nil errors, deferred mutation, and merged phis.

Exact-rule runs are clean on Glippy, `go-libraries/pkg/prompts`, and

their exact revisions and pre-existing state.

## Revisit Trigger

Follow result values beyond direct SSA identity only through a bounded
provenance model that rejects phis and dynamic dispatch unless every incoming
value agrees. Extend named-result support only with path-sensitive proof that
captures, address escape, defer, and asynchronous execution cannot mutate the
returned binding.
