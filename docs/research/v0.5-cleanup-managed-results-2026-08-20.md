# v0.5 Cleanup-Managed Result Facts, 2026-08-20

## Decision

Infer an exact cleanup-managed result fact when selected-module source proves
that a helper returns one stable direct local resource only after registering
that resource through `testing.T.Cleanup` on every normally returning path.
`resource-not-closed` consumes the fact for the exact call result instead of
assigning a second ownership obligation to the caller.

This is a narrow test-lifetime ownership contract. It does not infer arbitrary
cleanup registries, receiver effects, aliases, or generic finalizers.

## Observable Contract

The helper must return the same directly named local object at the exact result
index on every reachable normal return. The object cannot be reassigned,
aliased, address-escaped, or captured by another callback. Every path to those
returns must first call the exact promoted `testing.T.Cleanup` method on a
`*testing.T` receiver with a function-literal callback.

Every normally returning callback path must close the object either through a
direct `Close` method call or a statically resolved helper parameter whose
shared effect summary guarantees close. Observation-only callbacks,
conditional registration or close, goroutines, nested function literals,
replacement assignments, dynamic calls, aliases, non-testing cleanup APIs,
copied `testing.T` values, and disagreeing package variants remain unmanaged.

The native effect schema and cache component advance from version 5 to version
6. Cleanup-managed summaries use stable function and result identities, cross
selected-module package loads, participate in deterministic clone and digest
behavior, and never make dependency source a diagnostic target.

## Behavioral Evidence

The focused package regression initially reported all four caller acquisitions:
two cleanup-managed results, one observation-only callback, and one conditional
callback. The final fixture suppresses only the two proven managed results and
retains ten deliberately unmanaged cases covering observation, conditional
closure, conditional registration, asynchronous closure, nested closure,
replacement before cleanup, aliasing, callback replacement, callback escape,
and copied `testing.T` values. The alias and callback-mutation cases initially
produced false cleanup-managed facts before the stable-object boundary was
tightened. Direct method observation before registration remains supported.

An imported same-module helper using a guaranteed close helper produces no
caller diagnostic. Stable cross-load identity, digest sensitivity, deep clone,
and package-variant intersection have focused coverage. A disagreeing package
variant removes the summary; agreeing variants retain it. Existing
`resource-used-after-close` acquisition tracking intentionally remains
unchanged because test cleanup does not prove the resource is closed during
the caller; a focused close-then-read regression covers that interaction.

## Cost And Adoption

Five complete one-iteration `resource-not-closed` package benchmark samples on
Go 1.26.6, Darwin arm64, and an Apple M4 Max measured 72.60-84.55 ms,
2,106,776-2,679,944 B/op, and 16,865-17,309 allocs/op. Package loading remains
the dominant cost; this is directional rule evidence rather than a portable
release budget.

Non-mutating exact-rule dogfood remained clean on Glippy and
`go-libraries/pkg/prompts`. Against `go-libraries/pkg/http-client` at
`0e0240b1fdcefaa73619b8d0a5d0dfc778d9e2f0`, an exact same-revision comparison
reduced findings from 22 to 17. The five removed findings were produced by the
pre-change binary and omitted by the working-tree binary; the 17 retained
findings remain unclassified except for previously documented boundaries such
as cleanup through `Shutdown`, finalizer-like writers, fake closers, and
reentrant cleanup. The external repository head and pre-existing dirty state
were unchanged.

## Revisit Trigger

Revisit receiver terminal effects when real examples justify proving methods
such as `Shutdown` close their receiver on every normal path. Revisit callback
aliases or non-testing cleanup APIs only with an exact lifecycle contract that
preserves deterministic scheduling and conservative ownership joins.
