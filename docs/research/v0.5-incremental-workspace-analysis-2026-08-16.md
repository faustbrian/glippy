# v0.5 Bounded Incremental Workspace Analysis, 2026-08-16

## Decision

The first persistent LSP workspace-analysis boundary is implemented. One
backend session reuses finalized typed results for unaffected open packages,
reloads a changed package, and invalidates cached open reverse dependants from
the canonical package graph.

This is exact package-result reuse. It is not same-package incremental type
checking and does not retain `go/types`, CFG, or SSA graphs after a package run.

## Session Contract

- Compatible open files in one package still share one package load.
- Every package result records canonical root and transitive dependency package
  paths from the exact loaded graph.
- A changed or closed open package invalidates its own result and every cached
  result whose graph reaches that package.
- A new or otherwise unidentified package group conservatively invalidates the
  complete project-root session before its graph identity is known.
- An unaffected result is rebound to the current complete workspace overlay,
  so later code-action validation never receives the stale overlay that
  originally produced the result.
- Failed, incomplete, or filesystem-unverifiable analyses are not retained.
- The session retains at most eight package results within a deterministic
  256 MiB accounted-memory budget and evicts least-recently used entries first.
- Format-capable source is charged at sixteen times its exact bytes and compact
  dependency source at twice its bytes. The weight reflects their distinct
  retention classes without claiming to measure process RSS.
- One newest result may exceed the byte budget so a large active package remains
  usable, but it is retained alone.

## Filesystem And Policy Invalidation

Before reuse, Glippy revalidates exact bytes for captured non-overlay package
sources and configured baseline content. It also revalidates Go-file directory
membership plus `go.mod`, `go.sum`, `go.work`, and `go.work.sum` beneath the
selected root. Configuration and semantic-contract contents already participate
in the package-group configuration digest; source language and maximum analysis
tier remain explicit group-key inputs.

This covers ordinary editor overlays, on-disk sibling changes, added or removed
Go files, package dependency edits represented by another open package, module
selection, configured contracts, and baselines without trusting modification
times.

For capable clients, the server dynamically registers bounded workspace
watchers for Go, module/workspace, configuration, and TOML/JSON policy inputs.
Created, changed, and deleted file notifications are normalized to sorted unique
absolute paths and recorded in the backend session before a new snapshot is
analyzed. Exact captured files and tracked Go-source directories identify the
affected package; the retained transitive package graph also invalidates open
reverse dependants while unrelated package results remain reusable. This
includes captured local dependency source outside the selected project root
when the client reports its change.

## Behavioral Evidence

Focused regressions prove:

- an edit reloads one of two unrelated open packages while the other result is
  reused;
- the reused result receives the new complete overlay;
- editing an open dependency invalidates its open reverse dependant;
- changing a closed sibling source, adding a Go file, or changing `go.mod`
  reloads the package;
- compatible same-package buffers remain batched;
- unrelated package and external-test-package failures remain isolated; and
- the bounded cache deterministically excludes its least-recently used
  entries.
- superseded document analysis is canceled, pending intermediate versions are
  debounced, and only the newest exact version publishes diagnostics.
- final-document close and stale-snapshot completion reject queued actions,
  drain pending shutdown, and retain explicit request-cancellation precedence.
- repeated shutdown cannot replace the request already waiting for analysis,
  and protocol write failures remain session errors.
- workspace watching is registered through the standard client capability,
  watched changes trigger one refreshed open-document snapshot, and the backend
  receives bounded canonical local paths; and
- a watched dependency file invalidates its package and open reverse dependant
  without reloading an unrelated open package, even when file bytes are
  unchanged between snapshots;
- the retained-byte budget evicts older results before a newer result, retains
  one oversized newest result alone, and charges analyzed source automatically.

The red state performed two package loads after an unrelated edit. The fixed
state performs one.

The 2026-08-19 graph-first follow-up also removes root-wide invalidation when a
package group has no retained result. New groups are analyzed before reuse
decisions, and their exact returned root package paths invalidate only retained
entries whose root or dependency graph intersects those paths. Opening an
unrelated package therefore retains the known package result and performs only
the new package analysis. Opening a package that is a dependency of a retained
consumer still reloads that consumer. A failed or unidentified new graph falls
back to invalidating the complete selected root.

## Performance Evidence

The owned benchmark changes one of two unrelated packages after warming both.
Three three-operation samples on an Apple M4 Max, Darwin arm64, Go 1.26.5,
`GOMAXPROCS=1`, measured:

| Sample | Time | Bytes/op | Allocs/op | Package loads/op |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 34.22 ms | 558,114 | 3,926 | 1.000 |
| 2 | 35.87 ms | 558,144 | 3,929 | 1.000 |
| 3 | 28.55 ms | 557,989 | 3,927 | 1.000 |

The host was not isolated, so these are directional focused measurements rather
than release thresholds. The exact one-load functional metric is the durable
regression contract.

After adding accounted-memory eviction, three new three-operation samples on
the same host and toolchain measured 51.96 ms, 30.66 ms, and 33.14 ms; each
performed exactly 1.000 package load per operation and allocated
565,042-565,216 bytes with 3,982-3,983 allocations. This preserves the durable
reuse contract. It does not establish a portable editor-latency or RSS budget.

## Remaining Work

Typed analysis of the changed package still runs the complete package loader
and rebuilds its type, CFG, SSA, and effect representations. Persistent reusable
typed graphs, metadata-only package-graph discovery independent of analysis,
memory-aware worker scheduling, and portable editor latency/RSS budgets remain
active v0.5 work.
