# v0.6 Missed-Defect Queue, 2026-08-24

This queue records concrete gaps found while comparing the pinned public corpus
with Go vet and Staticcheck. It does not reserve rule IDs or bypass the normal
rule-admission evidence gate.

## General Ineffective Assignment

### Evidence

- NATS revision `1787eee035cf0253c201fa0f05afad92b6f296dc` assigns an error
  received from `errCh` to an existing variable and never reads the received
  value. The loop counts events, so the assignment is ineffective even though
  the channel receive is required.
- sqlc revision `99a7d7d0c7b913ded6a60a9d038ece99dcdf7892` computes a ClickHouse
  parameter name and numeric fallback, then constructs `ast.ParamRef` without
  reading the computed value. The assignment is stale or the intended name
  propagation is missing.
- Hugo revision `76a5e1880ab46688155b02e99bab9be2a6134492` increments an `end`
  offset while preparing missing-file debug context but never reads that
  offset. The assignment is stale or the intended path-segment diagnostic was
  never completed.
- Grafana revision `45a80328c0dd976720af0366efcad0787762b142` computes a
  quoted and optionally qualified `colName` in `pkg/util/xorm/session_find.go`
  but constructs the deleted-column condition without reading it. The
  assignment is stale or the intended qualified-column behavior is missing.
- Staticcheck reports all four as `SA4006`; the Go compiler and default
  `go vet` do not report any occurrence.

### Candidate Boundary

Investigate a general SSA-backed ineffective-assignment rule independently from
the admitted error-only `overwritten-error` rule. The candidate must preserve
RHS effects, distinguish deliberately ignored receives and calls from stale
destinations, handle joins and loop-carried uses, and avoid duplicating compiler
unused-variable diagnostics. Corpus evidence must determine whether it belongs
in `suspicious` or remains in `nursery`; these four occurrences justify
investigation but not default enablement.

No fix is presumed safe. Replacing a destination with `_`, deleting an
assignment, or restoring a missing consumer are observably different changes.

## Exact Suffix Removed As A Cutset

### Evidence

Grafana revision `45a80328c0dd976720af0366efcad0787762b142` contains two
occurrences in `pkg/util/xorm/dialect_postgres.go` that first recognize an exact
PostgreSQL type suffix and then pass that suffix to `strings.TrimRight`.
`TrimRight` treats its second argument as an unordered set of characters, not
an exact suffix. A default expression ending in another character from
`"::character varying"` or `"::timestamp without time zone"` can therefore be
truncated beyond the recognized suffix. Staticcheck reports both occurrences
as `SA1024`; Go vet does not report them.

### Candidate Boundary

Investigate a typed standard-library-misuse rule for exact-suffix intent passed
to `strings.Trim`, `TrimLeft`, or `TrimRight`. The rule must require evidence of
exact prefix or suffix intent, such as a dominating `HasPrefix` or `HasSuffix`
check with the same value, and must not report deliberate cutset use. Related
byte-slice APIs and constant propagation should be admitted only with separate
evidence.

A fix from `TrimRight(value, suffix)` to `TrimSuffix(value, suffix)` is safe
only when the exact-suffix guard and value identity are proven. Otherwise the
rule must remain diagnostic-only or suggestion-only.
