## Decision

Do not report an augmented impossible return-state comparison when all of the
following are true:

1. the source is a `_test.go` file;
2. the impossible edge is the true branch of an `if` statement;
3. the statement has no `else` branch;
4. the branch contains exactly one direct method call;
5. type information resolves that method to `testing.Error`, `Errorf`, `Fail`,
   `FailNow`, `Fatal`, or `Fatalf`; and
6. evaluating the method receiver and arguments is side-effect-free under a
   conservative syntax model.

The exception does not apply to upstream x/tools diagnostics, tautological
conditions whose branch always executes, nil dereferences, branches containing
other work, non-test files, or lookalike methods outside the `testing` package.
Calls, channel receives, indexing, dereferences, address-taking, composite
literals, function literals, pointer-indirect field selectors, operators, and
other unproven receiver or argument forms also retain the diagnostic. The
accepted operand set is limited to identifiers, literals, package-qualified
selectors, and value-field selectors. This is a typed contract-assertion
boundary rather than function-name or assertion-library matching.

## Behavioral Evidence

The focused regression first reported six diagnostics instead of the four
allowed by the initial contract. Expanded side-effect coverage then reported
six diagnostics instead of nine, proving that effectful receivers and
arguments were being hidden. After restricting operands, the focused case
passed with those diagnostics retained. A corpus-equivalent `testing.Errorf`
case plus `testing.Fail` then reported thirteen diagnostics instead of eleven;
admitting the complete exact testing failure-reporting set returned the case to
green. A final selector regression then reported eleven diagnostics instead of
twelve until pointer-indirect field evaluation was excluded while direct value
fields remained accepted. The final oracle binds every retained and permitted
case to its exact function-local source offset; removing `testing.Fail` from
the accepted set produced the extra diagnostic at that assertion's unique
offset before the mutation was reversed. Eligible assertions are indexed in
one syntax pass per function rather than rescanning the function for each SSA
comparison. The complete focused `TestNilness` suite also passes.
