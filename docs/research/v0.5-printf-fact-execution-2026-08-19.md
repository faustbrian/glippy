# v0.5 Exact Printf Fact Execution, 2026-08-19

## Decision

Glippy executes the fact-bearing `printf-arguments` analyzer through an
isolated, exact upstream `unitchecker` process. The ordinary process first runs
native and fact-free adapted rules, releases their package graph, and then
invokes the current Glippy executable as the `go vet` tool for the upstream
`printf` analyzer.

This is one audited execution mode, not a general executable-plugin surface.
The hidden mode is selected by the versioned
`GLIPPY_INTERNAL_UNITCHECKER=printf-v1` environment value. The catalog retains
the bounded in-process fact scheduler as a fallback for internal callers that
do not install the executable runner and for a future admitted analyzer whose
facts cannot use this exact boundary.

## Evidence And Alternatives

The retained-memory attribution identified `printf-arguments` dependency facts
as the first scale divergence. On pinned sqlc, the complete selected policy
peaked at 3,404,791,808 bytes while the same policy without
`printf-arguments` peaked at 1,335,197,696 bytes. Removing all SSA rules saved
only 4.3 percent.

The in-process package-wave prototype preserved stable fact snapshots but did
not meet the 2 GiB target:

- signature-filtered waves peaked at approximately 2.424 GB;
- the same workload without `printf-arguments` used approximately 1.441 GB;
- one real high-fanout dependency wave retained approximately 1.60 GiB.

The exact upstream unitchecker was then measured independently:

| Parallelism | Elapsed | Peak RSS |
| ---: | ---: | ---: |
| 1 | 61.77 s | 1,731,035,136 B |
| 2 | 36.90 s | 1,720,713,216 B |

Parallelism two materially reduced elapsed time without increasing retained
memory, so it is the fixed audited value. A combined probe measured the exact
printf phase at 33.37 seconds and 1,622,884,352 bytes, followed by the remaining
Glippy analysis at 2.21 seconds and 453,361,664 bytes.

## Execution Contract

The runner:

- invokes `go vet -json -p=2 -vettool=<current-glippy>`;
- serializes external fact execution through one runner semaphore;
- uses the package loader's read-only module, offline network, local toolchain,
  build-tag, GOOS, GOARCH, cgo, workspace, and cancellation policy;
- writes overlays only to a task-owned temporary directory and removes it after
  the command;
- limits standard output to 64 MiB and standard error to 1 MiB;
- accepts exit status one only when decoded diagnostics exist or the existing
  package load already established prerequisite errors;
- decodes concatenated package JSON documents deterministically;
- maps line and byte-column positions back to exact retained source versions
  without permitting a position to cross its physical line;
- ignores dependency and generated-file diagnostics that are not eligible
  Glippy targets;
- deduplicates test-variant diagnostics by complete mapped identity; and
- maps only declared suggested fixes into Glippy's source-versioned fix safety
  contract.

The Go command may compile packages and execute the Glippy vet tool. It does not
execute repository tests, generators, build scripts, or analyzed program code.

## Product Results

The production `benchmarks/peak-rss.sh` workload used:

- host: Apple M4 Max, Darwin arm64;
- toolchain: Go 1.26.6;
- corpus: `github.com/sqlc-dev/sqlc` at
  `8a7cddfbb9088666eb981645285d7699e71dcb54`;
- policy: default correctness plus `-Wsuspicious`;
- normalized diagnostic SHA-256:
  `030f4474aec74877307118376e77e8ad7254a46c32777242fd11e3223c7282d0`.

| Sample | Elapsed | Peak RSS |
| --- | ---: | ---: |
| cold | 20.330 s | 1,306,836,992 B |
| warm 1 | 1.600 s | 552,550,400 B |
| warm 2 | 1.530 s | 555,696,128 B |

All samples satisfy the 2,147,483,648-byte and 40-second reference-host gates,
and the normalized diagnostic digest is unchanged. Formatter samples used
288,391,168-326,844,416 bytes and completed in 0.350-0.630 seconds.

## Remaining Boundary

These measurements establish the reference-host implementation and durable
2 GiB default. They do not establish portable release budgets. Native Linux
and final-candidate macOS evidence must run the pinned typed workload before a
portable v0.5 memory claim is published.
