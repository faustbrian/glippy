## Recommended Findings

The recommended profile added ten actionable findings.

`http-response-body-not-closed` reports
`integration/networking/port_mapping_linux_test.go:267`. The polling callback
stores the first successful `http.Get` response and returns success, but the
test never closes its body. A successful poll therefore leaves the response
resource open.

Nine `unchecked-scanner-error` findings identify unobserved terminal scan
errors:

- `integration-cli/docker_cli_build_unix_test.go:177` converts a scanner
  failure into a generic missing-container-ID failure and loses the actual
  read or tokenization error;
- `integration-cli/docker_cli_daemon_test.go:2025` can accept a partial
  `/proc/self/mountinfo` scan as proof that a mountpoint is absent;
- `integration-cli/docker_cli_stats_test.go:137` lets its observer goroutine
  exit on a scan error, leaving the parent to fail only after a 30-second
  timeout;
- `integration/container/create_test.go:785` can silently skip the expected
  interface assertion after a scan error;
- `integration/plugin/logging/logging_linux_test.go:84` can accept a partial
  daemon log as proof that no broken-pipe message exists;
- `internal/testutil/fixtures/load/frozen.go:189` and line 198 can return an
  incomplete frozen-image map with a nil error; one terminal `Scanner.Err`
  check after the outer loop can satisfy both nested scan sites;
- `pkg/parsers/operatingsystem/operatingsystem_linux.go:57` can return a
  partial operating-system value with a nil error; and
- `pkg/tailfile/tailfile.go:37` can return partial tail output with a nil error.

These diagnostics match the suspicious rule's documented contract. They do
not justify a source-kind, test-file, in-memory-reader, early-break, or nested-
loop exception: each site either permits incomplete success or replaces the
terminal scanner error with delayed or materially weaker failure evidence.
