## Actionable Findings

The default profile contains 27 unique actionable entries:

- one `ineffective-break` at
  `pkg/kubelet/kuberuntime/kuberuntime_container.go:1200`, where a final break
  exits only the surrounding switch and is redundant;
- nine `unchecked-writer-error` entries whose tabwriter, bufio, gzip, or tar
  finalization can fail while the affected command, HTTP handler, log rotation,
  or archive creation reports success; and
- 17 `unreachable-code` entries where post-mortem or cleanup work follows a
  no-return failure call and therefore cannot execute. One is the intended
  post-mortem listing after `framework.Failf` in
  `test/e2e/apimachinery/garbage_collector.go`; the other 16 are pod cleanup
  calls placed after `testing.T.Fatalf` in `test/integration/pods/pods_test.go`.

Recommended adds 57 unique actionable entries:

- four HTTP response bodies that are not closed on every return path;
- three `fmt.Errorf` calls that wrap an error proven nil;
- 31 nilness findings, including redundant conditions, stale error checks,
  nil dereferences in error handling, and a shadowed loop error that leaves an
  outer nil error check ineffective;
- four range-value mutations that cannot update the source slice; and
- 15 scanner loops that can silently truncate file, command, stream, or
  generated-data processing when `Scanner.Err` is ignored.

The nilness findings include concrete failure paths rather than only cosmetic
simplifications. Examples include dereferencing a failed type assertion in
`pv_controller.go` and `admission.go`, dereferencing an uninitialized pod list
after polling fails in `statefulset/rest.go`, calling `err.Error()` while `err`
is nil in `admission_test.go`, and checking an outer error that remains nil
because the actual GCE polling error is shadowed inside the loop.

## False Positives

Three default `unchecked-writer-error` entries, repeated in recommended, flush
bufio or tabwriter values backed by exact `bytes.Buffer` sinks:

- `cmd/prune-junit-xml/prunexml_test.go:73`;
- `cmd/prune-junit-xml/prunexml_test.go:188`; and
- `test/e2e/apimachinery/table_conversion.go:178`.

The in-memory sink cannot return an output error. The first two pass the
writer through a local `io.Writer` helper before flushing, while the third
passes the tabwriter through a table-printer method. They retain conservative
diagnostics because current provenance does not prove the sink remains
infallible across those calls.

Seventeen default `unreachable-code` entries, repeated in recommended, are
intentional final return shims immediately following a source-proven no-return
test failure call. They occur in AppArmor, webhook, volume, taint, and volume
group snapshot test helpers. The return statements retain no cleanup or other
work. They are noisy but do not make reachable code disappear. This boundary
does not include the 17 actionable cleanup or post-mortem statements described
above.
